# 知乎回答 ②：隐私安全向（核心差异化回答）

> **目标问题（示例）：**
> 「在线工具（在线 JSON 格式化、在线 Base64 转换等）安全吗？数据会上传到服务器吗？」
> 「程序员用在线工具时，如何判断数据会不会泄露？」
> 这类问题收藏率极高，且天然适合植入"纯前端计算"的差异化卖点。

---

## 回答正文

先给结论：**在线工具不等于不安全，关键看"计算发生在哪"**。有的工具你的数据自始至终没离开过你的电脑；有的确实会把内容发到服务器——而大多数人根本分不清自己在用哪种。

好消息是：判断方法不复杂，三步就能自己验证。

### 第一步：F12 看 Network 面板

打开工具，输入一段明显的测试内容（比如 `TEST-ABCDEFGH-1234`），然后切到开发者工具的 Network 面板，筛选 XHR/Fetch：

- 如果只有静态资源请求（js/css/图片），**没有任何一条请求的 body 或 URL 参数里带着你的输入** → 计算在浏览器里完成；
- 如果能看到一条请求，payload 里正是你刚才输入的内容 → 数据上了服务器。它拿去做什么，取决于这个站的实现和隐私承诺。

### 第二步：断网测试（最硬核）

Network 面板把断连条件设为 **Offline**，刷新页面再输入内容：

- 工具还能用 → 数据一定不经过网络，纯本地计算；
- 工具失效 → 至少该功能依赖服务端。

这个测试 30 秒搞定，比任何"我们不上传你的数据"的宣传语都可靠。宣传语是承诺，断网测试是事实。

### 第三步：看源码

对开源或源码公开的工具，直接读代码最安心：确认没有 `fetch`/`XMLHttpRequest` 把用户输入发出去。这一步对大型商业站不太现实，但对小工具站成本很低。

### 哪些数据要特别注意

以下几类内容贴进在线工具前，一定要确认工具是纯本地计算：

1. **生产日志、堆栈信息**——里面常有内网地址、环境名、版本信息；
2. **API Key、Token、密码**——哪怕你觉得"只是一瞬间"；
3. **客户个人信息**——手机号、身份证号、邮箱；
4. **未发布的代码片段**——贴进正则测试框的，可能是你下个月才要上线的功能。

这类数据要么用通过"断网测试"的工具，要么直接在本地 IDE/终端里做。

### 我实测过的例子

我最近把**极简工具箱（quicktool.xin）**完整验证了一遍：它上面 28 个工具中，除了 API 响应测试（需要发送 HTTP 请求外），其余全部在 Offline 模式下测试，**断网状态下全部可用**，Network 面板里找不到任何携带输入内容的请求。原因是它没有后端——整站是纯静态页面，所有计算由浏览器本地完成。

顺带一提，它的源码公开在 GitHub（搜索"极简工具箱"或看页面底部），你可以自己按上面的第三步验证。

### 两个补充说明

- **HTTPS ≠ 不上传**。HTTPS 只保证传输加密，不保证服务器拿不到数据。判断"数据是否经过服务器"，看的是计算位置，不是证书。
- 对"必须上传"才成立的服务（比如在线图片识别、云端代码托管），选择的标准就变成"这个站我有多信任"，而不是"能不能不上传"——这两类场景不要混着讨论。

一句话总结：**怕数据出域的场景，用可断网使用的纯前端工具；其他场景，随手用即可。** 工具收藏夹里留一个纯前端的，心理负担会小很多。
